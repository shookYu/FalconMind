                      一、三种应用模式总览
================================================================================

FalconMind提供三种应用开发模式，满足不同场景和用户需求：

+----------------+  +----------------+  +----------------+
|  模式一        |  |  模式二        |  |  模式三        |
|  Builder开发   |  |  Viewer开发    |  |  SDK原生开发   |
+-------+--------+  +-------+--------+  +-------+--------+
        |                   |                   |
        v                   v                   v
+---------------+   +---------------+   +---------------+
| FalconMindBuilder | FalconMindViewer | FalconMindSDK |
| （边缘侧工具）  |  （地面端工具）  |  （SDK库）    |
+---------------+   +---------------+   +---------------+
        |                   |                   |
        v                   v                   v
+---------------+   +---------------+   +---------------+
| 可视化编排     |  | 表单+地图配置  |  | C++手搓代码   |
| 零代码/低代码  |  | 集群管理       |  | 完全定制      |
+---------------+   +---------------+   +---------------+

================================================================================
                   二、模式一：Builder开发（边缘侧）
================================================================================

2.1 基本定位
------------

    运行位置：UAV边缘设备（RK3588/RK3576）
    访问方式：浏览器访问 http://uav-ip:8080
    技术特点：零代码/低代码、可视化编排、即时部署
    适用场景：单UAV快速测试、现场调试、快速原型

2.3 使用流程
------------

    Step 1: 连接UAV WiFi/网线
        |
        v
    Step 2: 浏览器访问 http://uav-ip:8080
        |
        v
    Step 3: 可视化编排任务
        ├── 拖拽节点：开始 → 搜索区域 → 返航
        ├── 地图标绘：绘制搜索范围
        └── 配置参数：高度100m、速度8m/s
        |
        v
    Step 4: 点击"部署"按钮
        ├── Builder生成Flow JSON
        ├── FlowExecutor解释执行
        └── 无需编译，即时生效
        |
        v
    Step 5: UAV执行任务
        |
        v
    Step 6: 实时监控（可选）
        └── 3D地图显示UAV轨迹

2.4 核心特性
------------

    ✅ 零代码：拖拽式编排，无需编程基础
    ✅ 即时生效：Flow JSON解释执行，无需重新编译
    ✅ 离线可用：部署在UAV上，无需地面站参与
    ✅ 现场调试：现场发现问题，现场修改，现场验证
    ⚠️ 功能边界：受限于预置节点类型

2.5 典型场景
------------

    🔧 现场调试：外场测试时快速调整参数
    🚀 快速原型：验证任务流程可行性
    📋 标准任务：巡逻、搜索、拍照等常规任务
    👤 非程序员：产品、测试人员也能编排任务

                   三、模式二：Viewer开发（地面端）
================================================================================

3.1 基本定位
------------

    运行位置：地面PC或服务器
    访问方式：浏览器访问 http://ground-station-ip:8080
    技术特点：集群管理、任务分发、集中监控
    适用场景：多UAV集群管理、集中开发、协同规划

3.3 使用流程
------------

    Step 1: 操作员在地面站打开Viewer
        |
        v
    Step 2: 设计集群任务
        ├── 在地图上划定搜索区域
        ├── Voronoi分割区域
        └── 为每架UAV分配子区域
        |
        v
    Step 3: 任务生成与下发
        ├── Viewer生成任务JSON/Protobuf
        ├── 通过MQTT下发给各UAV的NodeAgent
        └── NodeAgent存储到SQLite（持久化）
        |
        v
    Step 4: UAV执行任务（离线自治）
        ├── NodeAgent解析任务
        ├── 调用SDK生成航点
        └── SDK上传航点到飞控
        |
        v
    Step 5: 实时监控与干预
        ├── 遥测数据通过WebSocket推送到Viewer
        ├── 发现目标自动上报
        └── 操作员可随时暂停/恢复/终止任务

3.4 核心特性
------------

    ✅ 集群视角：多机任务协调、冲突检测、负载均衡
    ✅ 集中存储：任务数据、遥测日志统一存储分析
    ✅ 实时监控：Cesium 3D地图实时显示机群位置
    ✅ 任务下发：批量任务分发，支持断点续传
    ⚠️ 网络依赖：需要与UAV保持通信

3.5 典型场景
------------

    👥 多机协同：机群搜索、编队飞行、协同搬运
    📊 数据管理：遥测数据长期存储与分析
    🏢 指挥中心：地面站集中管控整个机群
    🔄 任务调度：动态任务分配、实时冲突解决

3.6 Viewer与Builder的关系
--------------------------

    Viewer可以集成Builder功能，两种方式：
    
    方式A：Viewer内置Builder模块（共享后端）
    ----------------------------------------
    +------------------------------------------------+
    |             FalconMindViewer                   |
    |                                                |
    |   +----------------+  +--------------------+   |
    |   | Builder UI     |  | Viewer Backend     |   |
    |   | (Vue3组件)     |──▶| (FastAPI)          |   |
    |   |                |  | • UAV管理          |   |
    |   +----------------+  | • 任务下发         |   |
    |                       | • 集群监控         |   |
    |                       +--------------------+   |
    +------------------------------------------------+
    
    方式B：Viewer调用Builder API
    --------------------------

    | FalconMindViewer|------------------------▶|FalconMindBuilder|
    |   (地面端)     |   配置下发/状态查询     |   (边缘端)     |
    +----------------+                        +----------------+

4.4 使用流程
------------

    Step 1: 搭建开发环境
        ├── Ubuntu 20.04/22.04
        ├── CMake 3.16+, GCC 9+
        └── 安装SDK依赖（RKNN、OpenCV、MAVSDK）
        |
        v
    Step 2: 编写C++业务代码
        ├── 创建main.cpp
        ├── 调用SDK API（Easy/Core/Plugin）
        └── 实现自定义算法
        |
        v
    Step 3: 编译与测试
        ├── cmake .. -DCMAKE_BUILD_TYPE=Release
        ├── make -j4
        └── 本地SITL仿真测试
        |
        v
    Step 4: 部署到UAV
        ├── 交叉编译（ARM64）
        ├── 上传可执行文件到UAV
        └── 真实飞行测试

4.5 核心特性
------------

    ✅ 灵活度最高：无功能边界，可实现任何需求
    ✅ 性能最优：C++原生性能，无解释开销
    ✅ 算法定制：可实现Builder/Viewer不支持的新算法
    ✅ 深度集成：可集成第三方库（ROS2、自定义传感器）
    ⚠️ 技术门槛高：需要C++编程能力
    ⚠️ 开发周期长：编译、测试、部署流程较长

4.6 典型场景
------------

    🔬 算法研究：论文实验、新型检测/跟踪算法
    ⚡ 性能优化：极致延迟要求、高帧率处理
    🧩 深度定制：Builder/Viewer无法满足的特殊需求
    🔌 硬件集成：新传感器、自定义飞控协议

6.2 决策说明
------------

    场景1：需要多UAV集群管理
    ------------------------
    → 选择 Viewer开发（地面端）
    原因：Viewer提供集群管理、任务分发、集中监控能力

    场景2：需要复杂定制/新算法
    ------------------------
    → 选择 SDK原生开发（C++）
    原因：只有SDK能提供完全的灵活度和算法定制能力

    场景3：需要现场快速调试
    ------------------------
    → 选择 Builder开发（边缘侧）
    原因：Builder直连UAV，无需地面站，即时部署

    场景4：标准单UAV任务
    --------------------
    → 选择 Viewer开发（地面端）或 Builder开发（边缘侧）
    有地面站网络 → Viewer
    野外无网络 → Builder

    |                                                                      |
    |   关键说明：                                                         |
    |   • 三种模式是平级关系，都可以直接调用SDK                            |

7.2 数据流对比
--------------

    Builder模式数据流：
    ------------------
    
    用户 ──▶ Builder UI ──▶ Flow JSON ──▶ FlowExecutor ──▶ SDK ──▶ 飞控
    (浏览器)  (边缘端)      (配置生成)     (解释执行)      (能力层)


    Viewer模式数据流：
    ------------------
    
    操作员 ──▶ Viewer UI ──▶ 任务JSON ──▶ MQTT ──▶ NodeAgent ──▶ SDK ──▶ 飞控
    (地面端)   (地面端)      (任务生成)    (下发)    (边缘自治)   (能力层)


    SDK模式数据流：
    ------------------
    
    开发者 ──▶ C++代码 ──▶ 编译 ──▶ 可执行文件 ──▶ SDK ──▶ 飞控
    (PC)      (编写)     (构建)    (部署到UAV)     (能力层)
