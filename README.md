## 项目概述

FalconMind 是一套完整的无人机智能任务系统，包含地面控制平台（FalconMindConsole）、边缘侧开发工具（FalconMindBuilder）、边缘自治代理（NodeAgent）和软件开发工具包（FalconMindSDK）四大核心组件。**所有飞控连接均为真实实现，通过 MAVLink 协议直接连接 PX4/ArduPilot，无模拟、无 Mock。**

### 🎯 核心能力

| 能力域 | 说明 |
|--------|------|
| **🎮 统一控制台** | FalconMindConsole 提供集群管理、实时监控一站式界面 |
| **🔧 边缘开发** | FalconMindBuilder 提供零代码可视化编排，直连 UAV 即时部署 |
| **🔌 离线自治** | NodeAgent 实现 P0/P1/P2 三层离线自治，断网仍可自主决策 |
| **🔗 真实飞控** | MAVLink 直连 PX4/ArduPilot，支持 SITL 仿真和真实硬件 |
| **🧠 AI 感知** | 基于 Rockchip NPU 的 YOLO 目标检测与跟踪 |
| **📊 任务编排** | Pipeline + NodeFactory 架构，可视化流程设计 |

### 🆕 最新进展

**✅ FalconMindBuilder 边缘侧开发工具完成** - 可视化编排、即时部署、离线 Cesium 地图

**✅ NodeAgent 离线自治系统 (P0/P1/P2 全部完成)** - 15,000+ 行代码，250+ 测试用例

#### 核心关系说明

**1. Console → Builder（可选集成）**
- Console 作为"指挥中心"，可以**远程调用** Builder 的 API 获取 Flow 配置
- Builder 作为"独立工作室"，也可以**脱离 Console 独立运行**
- **数据流**：Console 下发任务参数 → Builder 本地编排 → Builder 部署到 UAV
- **适用场景**：地面站需要查看边缘设备上的任务配置，或远程协助调整参数

**2. Builder ↔ SDK（解释执行模式）**
- Builder 不直接生成可执行文件，而是生成 **Flow JSON 配置**
- SDK 的 **FlowExecutor** 解释执行 JSON，无需重新编译
- **数据流**：Builder 拖拽编排 → 生成 Flow JSON → SDK 解释执行 → 调用 MAVLink 控制 UAV
- **优势**：修改任务无需重新编译，秒级生效

**3. NodeAgent → SDK（API 调用模式）**
- NodeAgent 是 C++ 可执行程序，**编译时链接 SDK 库**
- NodeAgent 直接调用 SDK 的 C++ API，非解释执行
- **数据流**：NodeAgent 决策 → SDK API 调用 → 控制 UAV 或感知目标
- **优势**：运行效率高，适合实时自治决策

**4. 三者共同依赖 SDK（能力层）**

### 三种开发模式详解

#### 模式对比表

| 开发模式 | 使用工具 | 开发方式 | 运行位置 | 技术门槛 | 部署方式 | 适用场景 |
|----------|----------|----------|----------|----------|----------|----------|
| **Builder 开发** | FalconMindBuilder | 可视化编排 | UAV 边缘 | ⭐ 低 | 配置解释执行，秒级生效 | 现场调试、快速原型、简单任务 |
| **Console 开发** | FalconMindConsole | 表单+地图配置 | 地面站 | ⭐⭐ 中 | 任务下发到 UAV | 集群任务、集中管理、协同规划 |
| **SDK 原生开发** | FalconMindSDK | C++ 手搓代码 | 编译部署 | ⭐⭐⭐⭐ 高 | 编译生成可执行文件 | 复杂算法、性能优化、深度定制 |

#### 模式一：Builder 边缘开发（零代码/低代码）

**定位**：现场快速开发、无需地面站、单人单机任务

**工作流程**：
```
┌──────────────────────────────────────────────────────────────────┐
│                    Builder 开发流程                              │
├──────────────────────────────────────────────────────────────────┤
│                                                                   │
│  1. 现场部署 UAV                                                 │
│     └─> 连接 UAV WiFi / 网线                                      │
│     └─> 浏览器访问 http://uav-ip:8080                             │
│                                                                   │
│  2. 可视化编排任务                                               │
│     └─> 拖拽节点：开始 → 搜索区域 → 返航                          │
│     └─> 地图标绘：在昌平公园区域绘制搜索范围                        │
│     └─> 配置参数：高度 100m，速度 8m/s，模式 网格搜索               │
│                                                                   │
│  3. 即时部署（解释执行）                                          │
│     └─> 点击"部署"按钮                                             │
│     └─> Builder 生成 Flow JSON                                    │
│     └─> FlowExecutor 解释执行（无需编译）                           │
│     └─> UAV 立即开始执行任务                                       │
│                                                                   │
│  4. 实时监控（可选）                                              │
│     └─> 3D 地图显示 UAV 轨迹                                       │
│     └─> 查看遥测数据（高度、速度、电量）                            │
│                                                                   │
│  【无需地面站 · 无需编译 · 秒级生效】                              │
└──────────────────────────────────────────────────────────────────┘
```

**技术特点**：
- ✅ **零代码**：拖拽式编排，无需编程基础

### 场景2：单机搜索任务（有网络）

```
1. 操作员在 Console 设计任务
   └-> 在地图上划定搜索区域
   └-> 选择搜索模式（网格/螺旋）

   └-> 转换为 JSON/Protobuf 格式

   └-> 通过 SDK 的 MAVLink 接口上传给飞控

4. 飞行过程中
   └-> NodeAgent 使用 SDK 进行目标检测（RKNN）
   └-> 发现目标 -> 通过 MQTT 上报 Console
   └-> 实时遥测通过 WebSocket 推送到 Console

5. 任务完成
   └-> NodeAgent 自动返航（RTL）
   └-> 上传完整日志到 Console
```

```
  ├─ 继续执行当前任务（本地 SQLite 存储）

同时（P1 机组协同）：
  └─ UAV-001 作为 Leader 继续协调机群

  └─ 任务分配在机群内部完成

网络恢复后：
  └─ NodeAgent 批量同步离线期间的数据
  └─ 上报任务执行结果和发现的目标
```

```cpp
    .withPattern(SearchPattern::LAWN_MOWER)
```

**Core API（底层控制）**
```cpp
// Pipeline 节点编排，灵活组合
auto pipeline = std::make_shared<Pipeline>(config);
auto source = std::make_shared<SourceNode>("source");
auto detector = std::make_shared<DetectorNode>("det");
auto tracker = std::make_shared<TrackerNode>("track");

pipeline->addNode(source);
pipeline->addNode(detector);
pipeline->addNode(tracker);
pipeline->link("source", "out", "det", "in");
pipeline->link("det", "out", "track", "in");
```

## 🚀 快速开始

### 环境要求

- **操作系统**: Ubuntu 20.04/22.04 LTS
- **硬件平台**: x86_64 或 ARM64 (RK3588/RK3576/RV1126B)
- **依赖**: CMake 3.16+, GCC 9+, Python 3.11+, Node.js 18+

### 1. 启动 FalconMindBuilder（边缘开发）

```bash
cd FalconMindBuilder

# Docker 启动（推荐）
docker-compose up -d

# 访问 http://localhost:8080
# 默认显示昌平公园区域
```

### 2. 启动 FalconMindConsole（地面站）

```bash
cd FalconMindConsole
./start-dev.sh
# 访问 http://localhost:8080
```

### 3. 部署 NodeAgent（边缘自治）

```bash
# Docker 部署
cd FalconMindSDK/NodeAgent/docker
docker-compose up -d

# Systemd 部署
cd FalconMindSDK/NodeAgent/systemd
./install.sh
systemctl start nodeagent
```

### 4. 编译 SDK 并运行场景

```bash
cd FalconMindSDK/build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j4

# 运行 PoC 场景
cd ../scenarios/01_single_lawn_mower/build
./scenario_01_single_lawn_mower_real
```

## ❓ 常见误区澄清

**Q: Console、Builder、NodeAgent 有什么区别？**
- **Console** 是**地面指挥中心**，负责任务管理和集群监控，需要网络
- **Builder** 是**边缘开发工具**，部署在 UAV 上，提供可视化编排，**不依赖地面站**
- **NodeAgent** 是**边缘自治代理**，部署在 UAV 上，负责**离线决策**和任务执行

**Q: Builder 和 Console 的关系？**
- Builder 是**独立运行的边缘工具**，可以单独使用
- Console 可以**可选集成** Builder 的功能
- 类比：Builder = 本地 IDE（如 VS Code），Console = 云端协作平台（如 GitHub）

**Q: Builder 能离线使用吗？**
- ✅ **可以**。Builder 部署在 UAV 边缘设备上，浏览器访问即可使用
- ✅ **离线地图**：使用昌平公园默认位置，无需网络
- ⚠️ 如需下载卫星图瓦片，需要临时联网

**Q: 三者的版本如何管理？**
- SDK 作为库，版本号独立（v1.0.0）
- Builder 和 NodeAgent 依赖特定版本的 SDK
- Console 通过 API 版本与 Builder/NodeAgent 兼容
