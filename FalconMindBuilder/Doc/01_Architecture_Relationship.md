## 1. 产品定位澄清

### 1.1 运行位置

| 产品 | 运行位置 | 定位 | 功能 |
|------|---------|------|------|
| **FalconMindConsole** | **地面端** (PC/服务器) | 地面控制站 | 集群监控、任务管理、数据分析 |
| **FalconMindBuilder** | **边缘端** (RK3588/UAV) | 可视化开发工具 | 任务编排、即时部署、本地执行 |
| **FalconMindSDK** | **边缘端** (编译进应用) | 能力库 | 感知、规划、控制、通信 |

### 1.2 核心特性

**FalconMindBuilder**（边缘侧）：
- ✅ 运行在 UAV 边缘设备上（RK3588/RK3576）
- ✅ 提供 BS 架构的 Web UI，可直接浏览器访问
- ✅ 可视化编排任务，即时部署到本地
- ✅ 配置解释执行，无需编译
- ✅ 可以独立运行，不依赖 Console

**FalconMindConsole**（地面端）：
- ✅ 运行在地面的 PC 或服务器上
- ✅ 多 UAV 集群监控和管理
- ✅ 可以集成/内置 Builder 功能
- ✅ 也可以作为独立管理工具使用

## 3. 架构对比总结

### 3.1 三种开发方式对比

| 开发方式 | 运行位置 | 技术门槛 | 开发效率 | 适用场景 |
|----------|---------|---------|---------|---------|
| **Builder（边缘侧）** | UAV 边缘设备 | 低 | 高 | 快速原型、现场调试 |
| **Console（地面端）** | PC/服务器 | 低 | 高 | 集群管理、集中开发 |
| **SDK 纯手搓** | 编译部署 | 高 | 低 | 复杂定制、算法研究 |

### 3.2 Builder vs Console 对比

| 特性 | FalconMindBuilder | FalconMindConsole |
|------|-------------------|-------------------|
| **运行位置** | 边缘端 (RK3588) | 地面端 (PC/服务器) |
| **主要功能** | 可视化编排、即时部署 | 集群监控、任务管理 |
| **用户访问** | 浏览器访问 UAV IP | 浏览器访问地面站 |
| **UAV 数量** | 单 UAV（本地） | 多 UAV（集群） |
| **网络依赖** | 直连 UAV（局域网） | 需要 UAV 通信链路 |
| **是否可以独立运行** | ✅ 是 | ✅ 是 |
| **是否可以集成对方** | ✅ Console 可集成 Builder | ✅ 可调用 Builder API |

## 4. 配置解释执行架构（无编译）

### 4.1 核心设计

无论通过 Builder（边缘侧）还是 Console（地面端），最终都是生成配置并由 SDK FlowExecutor 解释执行。

```
开发方式                        配置生成                      执行
    │                              │                          │
    ▼                              ▼                          ▼
┌──────────────┐          ┌─────────────────┐          ┌──────────────────────┐
│ Builder UI   │─────────▶│ mission.json    │─────────▶│ SDK FlowExecutor     │
│ (边缘/地面)  │          │ {               │          │                      │
│              │          │   "nodes": [...]│          │ • loadFlow(json)     │
└──────────────┘          │   "edges": [...]│          │ • createNodes()      │
                          │ }               │          │ • Node::process()    │
                          └─────────────────┘          │   (解释执行)         │
                                                       └──────────────────────┘
```

**关键设计**：
- ✅ Builder 生成 JSON/YAML 配置（不是代码）
- ✅ SDK FlowExecutor 直接解释执行配置
- ✅ 无需编译、无需调试、在线编辑即时生效

### 4.2 执行流程

1. **用户开发**：
   - 方式A：登录 Builder（`http://uav-ip:8080`）
   - 方式B：使用 Console 内置 Builder
   - 方式C：直接写 JSON 配置文件

2. **配置生成**：
   - Builder 生成 `mission.json`
   - 包含节点定义、连接关系、参数配置

3. **配置下发**（如果是 Console）：
   - Console 通过 MQTT/HTTP 下发到 UAV

4. **解释执行**（在 UAV 上）：
   ```cpp
   // NodeAgent 或 Builder 后端调用
   FlowExecutor executor;
   executor.loadFlowFromFile("/data/missions/mission.json");
   executor.start();  // 解释执行，无需编译
   ```

## 6. 关键设计决策

### 6.1 架构设计原则

1. **Builder 运行在边缘侧**（不是 Console 的子模块）
   - Builder 是独立服务，部署在 UAV 上
   - 提供 BS 架构，可直接浏览器访问
   - 可以独立运行，不依赖 Console

2. **Console 和 Builder 可以集成**
   - Console 可以内置 Builder 功能（共享后端）
   - Console 可以通过 API 调用 Builder
   - 两者可以协同工作，也可以独立使用

3. **配置解释执行**（不是代码编译）
   - 无论 Builder 还是 Console，都生成 JSON 配置
   - SDK FlowExecutor 解释执行配置
   - 无需编译、在线编辑即时生效

4. **三种开发方式并存**
   - Builder（边缘侧）：快速可视化开发
   - Console（地面端）：集群管理和开发
   - SDK（纯代码）：深度定制和算法研究

### 6.2 使用场景推荐

| 场景 | 推荐方式 | 原因 |
|------|---------|------|
| 单 UAV 快速测试 | Builder（边缘侧） | 直连 UAV，无需地面站 |
| 现场调试 | Builder（边缘侧） | 本地开发，即时部署 |
| 多 UAV 集群 | Console（地面端） | 集中管理和监控 |
| 复杂算法定制 | SDK 纯手搓 | 灵活度高，可控性强 |
| 教学演示 | Builder 或 Console | 低门槛，可视化 |

## 8. 修正总结

### 8.1 修正内容

**之前的错误理解**：
- ❌ Builder 是 Console 的子模块（错）
- ❌ Builder 运行在地面端（错）

**正确的架构**：
- ✅ Builder 是**边缘侧**独立服务（运行在 UAV 上）
- ✅ Console 是**地面端**服务（运行在 PC/服务器上）
- ✅ Builder 和 Console **可以独立运行**
- ✅ Console **可以集成** Builder 功能
- ✅ 用户可以直接登录边缘侧的 Builder 开发

### 8.2 三种开发方式

1. **Builder（边缘侧）**：`http://uav-ip:8080` 直接访问 UAV 上的 Builder
2. **Console（地面端）**：地面站集中管理和开发，可内置 Builder
3. **SDK 纯手搓**：直接调用 SDK API，编写 C++ 代码
